# 客户 CRM 看板设计方案

## 目标

在 `ai-assistant/` 内提供一个仅本机使用的客户管理页面，把现有 Markdown 客户档案、客户索引和 pipeline 转换成清晰、可搜索、可维护的卡片式界面。

## 边界

- 应用及其运行代码只写入 `ai-assistant/`。
- 客户数据继续以 `ai-assistant/clients/*.md`、`clients/_index.md` 和 `leads/pipeline.md` 为准，不创建第二套 CRM 主数据。
- 不读写 `remotion/`；不向 `llm-wiki-mvp/` 写入任何 CRM 数据。
- 不删除或移动现有文件。

## 信息架构

单页看板包含四个区域：

1. 顶部摘要：客户总数、A 级数量、活跃跟进数量、待处理数量。
2. 筛选工具栏：关键词搜索，以及状态、等级、市场、来源、排序下拉框；支持一键重置。
3. 客户卡片网格：公司、联系人、地区、等级、得分、状态、来源、产品兴趣、下一步行动、更新时间和备注摘要。
4. 客户抽屉/弹窗：查看完整档案、修改状态/下一步行动/备注，以及录入新客户。

## 数据策略

- 服务启动时扫描 `clients/_index.md`、`leads/pipeline.md` 和 `clients/*.md`。
- 用 `client_id` 合并三处信息；档案字段优先，pipeline 提供最新状态和 next_action，索引补齐没有详情文件的客户。
- 新建客户时生成 `clients/{client_id}.md`，并在 `_index.md` 与 `pipeline.md` 追加对应记录。
- 编辑客户时更新对应档案中的字段和 `## Notes`，同时同步索引和 pipeline 中的状态、下一步行动与更新时间。
- 所有写入使用 UTF-8，并先在内存中完成校验；不覆盖无关段落或沟通记录。

## 技术方案

- 本地 Python 标准库 HTTP 服务，无需额外安装依赖。
- 原生 HTML/CSS/JavaScript 前端，响应式布局，适配桌面宽屏与窄屏。
- JSON API：
  - `GET /api/clients`：返回合并后的客户列表与筛选枚举。
  - `POST /api/clients`：校验并新增客户。
  - `PATCH /api/clients/{client_id}`：更新允许编辑的字段、状态和备注。
  - `GET /api/health`：启动与联调用健康检查。
- UI 使用可访问的原生控件，弹窗支持关闭按钮与 Escape，所有操作给出成功/失败提示。

## 视觉方向

采用温暖的香氛工作室风格：米白背景、深墨绿主色、琥珀色强调。卡片用状态色条和等级徽章形成快速视觉识别，信息密度高但保持足够留白，不使用通用后台模板的冷硬风格。

## 验收标准

- 能展示现有客户，且总数与合并数据一致。
- 每位客户都有独立卡片，并可打开完整详情。
- 搜索及状态、等级、市场、来源下拉筛选工作正常。
- 可通过表单录入 Alibaba 或其他来源客户并填写备注，刷新后仍存在。
- 可编辑客户状态、下一步行动和备注，刷新后仍存在。
- 空状态、无结果、表单校验、保存失败均有清晰反馈。
- 页面在常见桌面宽度与窄屏下无明显溢出或遮挡。
- 桌面提供一个 `.bat`，双击即可启动服务并打开页面。
- 浏览器联调覆盖页面加载、筛选、搜索、详情弹窗、录入校验、保存及编辑流程。
