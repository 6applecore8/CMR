# CRM 双板块与阿里产品信息拆分设计

## 目标

在现有本地客户 CRM 中把客户明确分成两个可点击切换的工作区：

- **阿里客户**：由业务员手工录入，所有字段均可选。
- **邮件客户**：承接现有非 Alibaba 来源客户，保留现有跟进与编辑能力。

同时提供阿里客户产品原文的自动结构化拆分，减少向 Excel 不同列重复抄写的工作。

## 客户归类规则

- `source` 包含 `alibaba` 或 `阿里`（忽略大小写）时归为“阿里客户”。
- 其余现有客户归为“邮件客户”。这只是界面分组，不移动或复制原始客户档案。
- 新增阿里客户固定写入 `source: alibaba`；新增邮件客户写入 `source: email_manual`。

## 页面交互

1. 在看板主区域增加“阿里客户 / 邮件客户”分段标签，显示各自数量；点击后切换卡片、统计和新增按钮语义。
2. 搜索、状态、等级、市场和排序筛选只作用于当前板块。
3. 阿里客户卡片优先显示姓名、地址、电话和产品摘要；邮件客户继续优先显示公司、邮箱、地区和下一步行动。
4. “新增客户”弹窗根据当前板块切换：
   - 阿里客户：姓名、公司、地址、电话、产品原文、产品拆分结果、备注等全部非必填。
   - 邮件客户：沿用原有资料字段与校验。
5. 阿里板块提供“导出 Excel CSV”，使用 UTF-8 BOM，包含客户、联系方式和所有产品拆分列。

## 客户卡片分页

- 分页在浏览器端对“当前板块完成搜索、筛选和排序后的客户集合”执行，不改变后端客户数据，也不移动档案。
- 默认每页显示 12 张卡片，可切换为 12、24、48；页大小在本次页面会话中保持。
- 分页栏显示当前记录范围、总记录数、当前页/总页数，并提供上一页、下一页和页码按钮。
- 切换阿里/邮件板块、搜索、筛选、排序或重置筛选时回到第 1 页；刷新数据后将当前页限制到仍然存在的页码范围。
- 没有结果或只有一页时隐藏无意义的页码按钮，但仍保留清晰的结果数量；移动端分页控件允许换行，不产生横向滚动。
- 分页按钮使用原生 button、禁用态和 `aria-current="page"`，键盘可操作；翻页后把“客户列表”标题滚入可见区域，但尊重减少动态效果设置。

## 阿里产品信息结构

保留原文并写入以下可编辑字段：

| 字段 | 用途 |
|---|---|
| `product_raw` | 客户发送的完整原文 |
| `product_name` | 产品/品名 |
| `fragrance_requirement` | 香型、参考香或香味要求 |
| `product_application` | 香水、香皂、蜡烛、扩香等用途 |
| `product_quantity` | 数量及单位 |
| `product_specification` | 容量、浓度、包装或单件规格 |
| `target_price` | 目标价或预算 |
| `other_requirements` | 无法归入以上列的要求 |
| `product_codes` | 批量产品的内部编码，一行一个并保持客户原文顺序 |
| `product_names` | 批量产品名称，一行一个；与内部编码按行对应 |

旧字段 `product_interest` 保留，用产品名称/用途生成简短摘要，避免破坏既有搜索和卡片展示。

## 自动拆分

- 新增 `POST /api/product-info/parse`，输入 `raw_text`，返回上述结构化字段。
- 解析支持中文和英文常见标签，例如“产品/Product、香型/Scent、用途/Application、数量/Qty、规格/Size、价格/Target price、要求/Requirement”。
- 支持换行、逗号、分号和连续文本中的 `键: 值`/`键=值` 格式。
- 对没有标签的文本补充数量、单位、价格和常见应用词启发式识别。
- 解析只提供建议，不覆盖用户随后手动修改的字段；原文始终保留。
- 服务日志只记录字符数、命中的字段名和耗时，不记录产品原文。

## 批量产品编码与名称隔离

- 同一次粘贴支持 10 条以上产品，优先识别“内部编码/产品编码/Code/SKU/Item No.”与“产品名称/Product name/Name”等中英文标签。
- 同时支持常见逐行格式，例如 `SL-001 | Rose Fragrance Oil`、`SL-001 Rose Fragrance Oil`、制表符和冒号分隔。
- 解析结果保持原始顺序，并生成两份可编辑的换行列表：`product_codes` 与 `product_names`。同一行代表同一产品，缺失的一侧保留空行，避免复制到 Excel 后错位。
- 页面以两列展示，分别提供“复制全部编码”和“复制全部名称”；复制内容每行一个值，可直接粘贴到 Excel 单列。
- 另提供逐行预览和识别数量。自动结果仍遵循“用户手工修改后不再覆盖”的规则。
- 批量字段写入客户 Markdown，并在 Alibaba CSV 中作为两个独立列导出；日志不得记录编码或名称原文。

## 数据兼容性

- 新字段追加到客户 Markdown 的 Profile 表中；旧档案无需迁移即可继续读取。
- 将旧 `address` 字段解析为独立地址，不再混入 `country_region`。
- Alibaba 新建允许公司为空；若姓名和公司都为空，生成“未命名阿里客户”显示名及唯一 `client_id`。
- 非 Alibaba 新建仍要求公司名称，避免改变邮件客户的现有工作流。

## 验收标准

- 两个板块能点击切换，数量与来源归类一致。
- 阿里新增表单无 HTML `required` 限制，空表单也能安全创建档案。
- 姓名、地址、电话、产品原文和备注刷新后仍存在。
- 粘贴中英文混合产品原文后能自动拆分，并允许逐列修改。
- 一次粘贴至少 12 条“内部编码 + 产品名称”样例时，顺序和行对应关系保持一致，两列可分别一键复制。
- 手工修改批量编码或名称列后再次改变原文，手工列不被覆盖；重开新增弹窗后恢复自动建议状态。
- CSV 能被 Excel 按列打开，中文不乱码，字段顺序稳定。
- 邮件客户的原有搜索、筛选、详情、编辑功能不回归。
- 邮件客户 76 条数据默认显示 12 张卡片并产生 7 页；上一页/下一页、页码、页大小与筛选后页数均正确。
- 自动化测试覆盖归类、空阿里客户、新字段持久化、产品解析和 CSV 关键结构。
- 浏览器审核覆盖板块切换、无必填录入、产品自动拆分、CSV 触发、响应式布局及控制台错误。
