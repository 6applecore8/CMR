# Agent 开发简历：跨电脑交接

> 本文件会出现在公开 GitHub 仓库中，只记录工作目标和协作边界，不存放简历原件、个人联系方式、真实客户资料、Wiki 原文或任何密钥。

## 当前目标

帮助用户制作一份适合投递初级 AI 应用开发 / Agent 开发岗位的中文简历，突出真实的业务问题、本人贡献、技术实现和可验证结果，并为后续面试准备清晰的项目讲解。

## 继续工作前

1. 请用户在另一台电脑选择需要使用的最新简历和目标岗位信息；不要猜测本机路径、自动读取未授权的文件或将简历原件上传到公开仓库。
2. 如用户授权，先阅读该电脑上的项目资料和个人 Wiki，区分代码、设计、测试报告与实际业务使用。Wiki 内容默认为本地私有资料，不自动复制到此公开仓库或发送给外部模型。
3. 核对项目真实时间线、个人负责范围和实际验证状态。确认个人后续迭代与实习期间工作分别发生在什么时间，再归类到简历。
4. 对缺失或冲突信息提出简短具体的问题；没有证据的数字、上线规模和项目成果不应编造。

## 简历重点

- Agent 应用：根据实际经历选择工具调用、工作流、状态管理、权限控制、异常处理与评估等内容；未实现或仅有方案的能力不得写成已上线。
- RAG 与数据来源：如确实实现，说明文档解析、分块、检索、模型调用、引用来源和证据不足处理；区分开发实现与实际联调验收。
- 外贸 CRM：如果用户确实在实习期间参与相关工作，可将该期间真实职责写入实习经历；实习之外的个人开发与后续迭代写在项目经历。若并非实习工作，则不要虚构实习关系。
- 模型蒸馏：只保留用户确认过的实际职责，不将参与的一部分写成独立完成全流程。
- 数据量化：优先使用有测试记录的真实指标，并注明样本量、基线、时间范围和计算方法。没有依据时用清晰的工程行动与结果代替，不创造数字。
- 项目责任：使用者需要能解释架构、关键代码、个人贡献和问题排查；合理说明使用 AI 辅助开发的实际情况。

## 建议产物

1. 一版面向 Agent 应用开发岗位的简历正文，先用文字给用户核对事实，再按用户要求制作文件。
2. 每个项目的一分钟介绍与常见面试追问，清楚区分本人工作、团队工作和待完成事项。
3. 如有目标职位描述，将真实经历与岗位需求逐项映射；有缺口时明确说明，不靠编造补齐。

## 当前仓库与数据边界

- 这是 CMR 的 GitHub 仓库；公开仓库中的默认分支不一定包含其他电脑或其他分支上尚未提交的工作。任何实现状态需以实际代码和测试为准。
- 不要将本地 Wiki、客户档案、报价、简历原件、API Key、令牌、密码或配置密钥提交到 GitHub。
- 简历写作 Skill 位于 skills/resume-writing/SKILL.md，是针对简历任务新编写的指导；使用前阅读其说明，不能用它替代事实核实。
- 克隆仓库后，可在另一台电脑对助手说：请阅读 docs/AGENT_RESUME_HANDOFF.md 和 skills/resume-writing/SKILL.md，先核对我授权的简历与 Wiki，再帮我制作 Agent 开发简历。仅将文件放进仓库不会自动安装或启用 Skill。
